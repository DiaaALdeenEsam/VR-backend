Patient Simulator Internals البنية الداخلية لمحاكي المريض

A from-scratch FastAPI backend for training doctors on simulated patient cases — built in strict Clean Architecture (Ports & Adapters), backed by a real SQLite database, and grown feature by feature: a chat-driven patient simulation powered by a local LLM, OSCE-style scoring, and a full voice pipeline. This report explains how it's built, why it's built that way, and how a request actually moves through it. واجهة خلفية مبنية بالكامل من الصفر بإطار FastAPI لتدريب الأطباء على حالات مرضية محاكاة — مبنية ببنية نظيفة صارمة (Ports & Adapters)، مدعومة بقاعدة بيانات SQLite حقيقية، ومطوَّرة ميزة تلو الأخرى: محاكاة مريض تعتمد على المحادثة مدعومة بنموذج لغوي محلي، تقييم بأسلوب OSCE، وخط أنابيب صوتي كامل. يشرح هذا التقرير كيف بُني هذا كله، ولماذا بُني بهذه الطريقة تحديدًا، وكيف يتحرك الطلب فعليًا عبره.

01 Overviewلمحة عامة

The product: a doctor opens a clinical scenario, converses with a simulated patient (by text or by voice), orders diagnostic tests, answers OSCE-style quiz questions, and finally gets a structured evaluation of the whole encounter. Everything the doctor doesn't already know — the underlying diagnosis, the answer key, test results — stays server-side until the corresponding in-session action reveals it. المنتج: يفتح الطبيب سيناريو سريريًا، يحاور مريضًا محاكى (نصًا أو صوتًا)، يطلب فحوصات تشخيصية، يجيب عن أسئلة اختبار بأسلوب OSCE، ثم يحصل أخيرًا على تقييم منظّم للمواجهة بأكملها. كل ما لا يُفترض أن يعرفه الطبيب مسبقًا — التشخيص الفعلي، مفتاح الإجابات، نتائج الفحوصات — يبقى على الخادم حتى يكشفه الإجراء المقابل ضمن الجلسة.

What was previously going to be scattered JSON files and in-memory dicts is instead a real SQLite database, reached exclusively through a layered, testable backend: ما كان سيصبح ملفات JSON متفرقة وقواميس في الذاكرة أصبح بدلاً من ذلك قاعدة بيانات SQLite حقيقية، لا يُوصَل إليها إلا عبر واجهة خلفية مُقسَّمة إلى طبقات وقابلة للاختبار:

  • Persistenceالحفظ (Persistence) — SQLModel table models, an async engine, and Alembic migrations as the single source of schema truth (no create_all() anywhere). — نماذج جداول SQLModel، ومحرك غير متزامن، وهجرات Alembic كمصدر وحيد للحقيقة بخصوص المخطط (لا استدعاء لـ create_all() في أي مكان).
  • Domain logicمنطق النطاق (Domain) — plain Python entities and abstract ports, with zero knowledge of HTTP, SQL, or any ML library. — كيانات Python صرفة ومنافذ (ports) مجرّدة، بلا أي معرفة بـ HTTP أو SQL أو أي مكتبة تعلّم آلي.
  • Pluggable intelligenceذكاء قابل للتوصيل — every "smart" capability (patient replies, evaluation, speech-to-text, text-to-speech) sits behind an interface with a free stub implementation and a real local-model implementation, swappable by one config setting. — كل قدرة "ذكية" (ردود المريض، التقييم، تحويل الكلام إلى نص، تحويل النص إلى كلام) تقف خلف واجهة تجريدية لها تنفيذ وهمي مجاني وتنفيذ حقيقي بنموذج محلي، قابلان للتبديل بإعداد واحد فقط.
  • Voice, end to endالصوت من طرف إلى طرف — upload or stream audio in, get transcribed text, a persisted chat turn, and synthesized speech back out. — ارفع الصوت أو ابثّه، واحصل على نص مفرَّغ، ودورة محادثة محفوظة، وكلامًا مُصنَّعًا في المقابل.

02 Architectureالبنية المعمارية

Four layers, strict inward dependency: api and infrastructure depend on application and domain — never the reverse. A dedicated test (test_architecture_boundaries.py) parses every file under domain/ and application/ with Python's ast module and fails the build the moment one of them imports SQLModel, FastAPI, SQLAlchemy, or any ML/audio library. This isn't a comment promising discipline — it's enforced on every test run. أربع طبقات، باعتماد صارم يتجه إلى الداخل: api وinfrastructure تعتمدان على application وdomain — لا العكس أبدًا. اختبار مخصص (test_architecture_boundaries.py) يحلّل كل ملف ضمن domain/ وapplication/ باستخدام وحدة ast في بايثون، ويُفشل البناء فور استيراد أحدها لـ SQLModel أو FastAPI أو SQLAlchemy أو أي مكتبة تعلّم آلي/صوت. هذه ليست تعليقًا يعِد بالانضباط — بل قاعدة مُنفَّذة في كل تشغيل للاختبارات.

  • app/domain/ — entities.py (plain dataclasses), repositories.py (abstract repository interfaces and the four "port" interfaces below), exceptions.py. — entities.py (كيانات dataclasses صرفة)، repositories.py (واجهات مستودعات مجرّدة، وواجهات "المنافذ" الأربعة أدناه أيضًا)، exceptions.py.
  • app/application/use_cases/ — one class per user-facing action, each constructor-injected with a AbstractUnitOfWork and whatever port(s) it needs. — صنف واحد لكل إجراء يواجه المستخدم، يُحقَن في مُنشئه بـ AbstractUnitOfWork وأي منفذ (منافذ) يحتاجها.
  • app/infrastructure/ — SQLModel models, the async engine, concrete repository implementations, and every stub/real port adapter. — نماذج SQLModel، والمحرك غير المتزامن، وتنفيذات المستودعات الفعلية، وكل محوّل منفذ وهمي أو حقيقي.
  • app/api/ — thin FastAPI routers: parse request, call a use case via Depends(), map the result to a Pydantic schema. No business logic. — راوترات FastAPI رقيقة: تُحلّل الطلب، تستدعي حالة استخدام عبر Depends()، وتُحوّل الناتج إلى مخطط Pydantic. بلا أي منطق عمل.

01

Foundation: the layered backend itselfالأساس: الواجهة الخلفية المُقسَّمة نفسها

The whole clean-architecture skeleton, from nothing: 8 SQLModel tables behind Alembic migrations, an async engine, one repository implementation per aggregate wrapped in a SqlAlchemyUnitOfWork, and 10 REST endpoints covering scenarios, sessions, chat, test ordering, quiz answers, and session review — all with a strict no-leak rule (test results, answer keys, and answer correctness are never returned before the action that's supposed to reveal them). الهيكل الكامل للبنية النظيفة، من الصفر: 8 جداول SQLModel خلف هجرات Alembic، ومحرك غير متزامن، وتنفيذ مستودع واحد لكل تجميعة ملفوف في SqlAlchemyUnitOfWork، و10 نقاط نهاية REST تغطي السيناريوهات والجلسات والمحادثة وطلب الفحوصات وإجابات الاختبار ومراجعة الجلسة — كل ذلك بقاعدة صارمة لعدم التسريب (نتائج الفحوصات، ومفاتيح الإجابات، وصحة الإجابات لا تُعاد أبدًا قبل الإجراء المفترض أن يكشفها).

02

A real local patient — Qwen2.5-0.5B-Instructمريض محلي حقيقي — Qwen2.5-0.5B-Instruct

Replaced the chat stub with a genuine local LLM: transformers + CPU-only torch, lazily loaded once per process and cached, kept strictly in character and in Arabic by its system prompt. Every failure mode (no network on first download, out of memory, deps missing) falls back to a labeled placeholder reply instead of crashing the request. استبدال النموذج البديل للمحادثة بنموذج لغوي محلي حقيقي: transformers مع torch على المعالج فقط (CPU)، يُحمَّل بتكاسل مرة واحدة لكل عملية ويبقى مخزَّنًا، ويُبقيه موجّه النظام ضمن الشخصية وباللغة العربية بدقة. كل نمط فشل (لا اتصال إنترنت عند أول تنزيل، نفاد الذاكرة، اعتماديات ناقصة) يعود إلى رد بديل موسوم بوضوح بدلاً من تعطّل الطلب.

03

OSCE-style evaluationتقييم بأسلوب OSCE

A new EvaluationGenerator port and POST /sessions/{id}/evaluate: scores the encounter against the scenario's gold_standard, with a per-criterion pass/fail breakdown. Generated on demand, never persisted — call it again after the doctor does more in the session for an updated read. منفذ جديد EvaluationGenerator ونقطة نهاية POST /sessions/{id}/evaluate: يُقيّم المواجهة مقابل gold_standard الخاص بالسيناريو، مع تفصيل لكل معيار بنجاح/فشل. يُولَّد عند الطلب فقط ولا يُخزَّن أبدًا — استدعه مرة أخرى بعد أن يفعل الطبيب المزيد ضمن الجلسة للحصول على قراءة محدَّثة.

04

Rich seed data + full end-to-end coverageبيانات تمهيدية غنية + تغطية كاملة من طرف إلى طرف

A realistic Arabic scenario set (seed_data/) — appendicitis with a gold standard, gastritis without one, three test categories, eight tests with clinically plausible results, and OSCE questions for both scenarios — plus a dedicated E2E suite that walks all 11 REST endpoints in one flow, seeded via the real seed-script functions (so it doubles as a regression test for the seed script itself). A scripts/smoke_test.py runner and a curl walkthrough cover manual testing. مجموعة سيناريوهات عربية واقعية (seed_data/) — التهاب الزائدة الدودية بمعيار مرجعي، والتهاب المعدة بلا معيار، وثلاث تصنيفات فحوصات، وثمانية فحوصات بنتائج معقولة سريريًا، وأسئلة OSCE لكلا السيناريوهين — بالإضافة إلى حزمة اختبار شاملة (E2E) تمر بكل نقاط REST الإحدى عشرة في تدفق واحد، مزروعة عبر دوال سكربت التزريع الفعلية (فتُصبح بذلك اختبار ارتداد لسكربت التزريع نفسه أيضًا). سكربت تشغيل scripts/smoke_test.py ودليل عبر curl يغطيان الاختبار اليدوي.

05

Voice pipeline: STT + TTSخط أنابيب صوتي: تحويل الكلام إلى نص والعكس

Two new ports (SpeechToTextPort, TextToSpeechPort) and three endpoints: POST /transcribe, POST /sessions/{id}/chat-voice (audio in → transcript + persisted chat turn + synthesized reply audio out), and WS /ws/voice for the same flow over a WebSocket, one utterance per binary frame. Speech-to-text is a local faster-whisper "tiny" model forced to Arabic; text-to-speech is gTTS. ProcessVoiceChatUseCase composes PostMessageUseCase directly rather than duplicating chat persistence — the one place in this codebase a use case depends on another use case instead of only on ports. منفذان جديدان (SpeechToTextPort، TextToSpeechPort) وثلاث نقاط نهاية: POST /transcribe، وPOST /sessions/{id}/chat-voice (صوت يدخل ← نص مفرّغ + دورة محادثة محفوظة + صوت رد مُصنَّع يخرج)، وWS /ws/voice لنفس التدفق عبر WebSocket، نطق واحد لكل إطار ثنائي. تحويل الكلام إلى نص محلي عبر نموذج faster-whisper "tiny" مُجبَر على العربية؛ وتحويل النص إلى كلام عبر gTTS. ProcessVoiceChatUseCase يستدعي PostMessageUseCase مباشرة بدلاً من تكرار منطق حفظ المحادثة — المكان الوحيد في هذا المشروع الذي تعتمد فيه حالة استخدام على حالة استخدام أخرى بدلاً من الاعتماد على المنافذ فقط.

05 A Doctor's Workflowسير عمل الطبيب

What actually happens, end to end, across everything above: ما يحدث فعليًا، من البداية للنهاية، عبر كل ما سبق:

  2. Start a sessionابدأ جلسة POST /sessions gets a session id used for everything below.يحصل على معرّف جلسة يُستخدم في كل ما يلي.
  3. Interview the patientاستجوب المريض POST /sessions/{id}/messages or its voice equivalent — a chat turn either way, same persisted history.أو مكافئه الصوتي — دورة محادثة في الحالتين، بنفس السجل المحفوظ.
  4. Order investigationsاطلب الفحوصات GET /test-categories/{id}/tests → POST /sessions/{id}/tests results are invisible until this exact call.النتائج غير مرئية حتى هذا الاستدعاء تحديدًا.
  5. Answer the quizأجب عن الاختبار GET /scenarios/{id}/questions → POST /sessions/{id}/answers no answer key leaks, and no correctness leaks back either; re-answering upserts.لا يتسرّب مفتاح الإجابة، ولا تتسرّب الصحة أيضًا؛ إعادة الإجابة تُحدِّث السجل السابق.

  7. Get evaluatedاحصل على تقييم POST /sessions/{id}/evaluate an OSCE-style score and per-criterion feedback, generated fresh each call.علامة بأسلوب OSCE وملاحظات لكل معيار، تُولَّد من جديد في كل استدعاء.

07 Design Principlesمبادئ التصميم

The rules that repeat across every feature above, not just the first one: القواعد التي تتكرر عبر كل ميزة أعلاه، لا الميزة الأولى فقط:

01 · Ports & Adaptersالمنافذ والمحوّلات

Every external capability — LLM reply, evaluation, STT, TTS — is an abstract interface in domain/ with a free stub and a real implementation in infrastructure/, picked by one Settings field. كل قدرة خارجية — رد النموذج اللغوي، التقييم، تحويل الكلام لنص، تحويل النص لكلام — واجهة مجرّدة في domain/ لها نسخة وهمية مجانية وتنفيذ حقيقي في infrastructure/، يُختار عبر حقل واحد في Settings.

02 · Graceful degradationتدهور رشيق

Every real adapter catches its own failures and falls back to its stub sibling. Nothing in this backend crashes a request because a model failed to load. كل محوّل حقيقي يلتقط أخطاءه الخاصة ويعود إلى نظيره الوهمي. لا شيء في هذه الواجهة الخلفية يُسقط طلبًا بسبب فشل تحميل نموذج.

03 · One transaction, one outcomeمعاملة واحدة، نتيجة واحدة

Every mutating use case opens async with uow: once and commits once. A failure partway through rolls back — never a partial write. كل حالة استخدام معدِّلة تفتح async with uow: مرة واحدة وتُنفِّذ commit مرة واحدة. أي فشل في المنتصف يُلغي التغييرات — لا كتابة جزئية أبدًا.

04 · No premature leaksلا تسريب مبكر

Case text, gold standards, test results, answer keys, and answer correctness are each returned by exactly one action — never earlier. نص الحالة، والمعايير المرجعية، ونتائج الفحوصات، ومفاتيح الإجابات، وصحة الإجابات — كل منها يُعاد عبر إجراء واحد فقط، لا قبله أبدًا.

05 · Enforced, not promisedمُنفَّذ لا مجرد وعد

test_architecture_boundaries.py statically checks every file in domain/ and application/ for forbidden imports — a broken layer boundary fails CI, not code review. test_architecture_boundaries.py يفحص إحصائيًا كل ملف ضمن domain/ وapplication/ بحثًا عن استيرادات محظورة — أي خرق لحدود الطبقات يُفشل الاختبار الآلي، لا مراجعة الكود فقط.

06 · Convention over literal specالاتفاقية أولى من نص الطلب

Where a feature request's literal wording conflicted with an established pattern (a flat route vs. session-nesting, a bare exception vs. the domain-error hierarchy), the existing convention won — each time, documented in place. حين تعارضت الصياغة الحرفية لطلب ميزة ما مع نمط قائم فعلاً (مسار مسطّح مقابل تعشيش داخل الجلسة، استثناء مجرّد مقابل هرمية أخطاء النطاق)، انتصرت الاتفاقية القائمة — في كل مرة، وموثَّقة في مكانها.

08 Testing & Verificationالاختبار والتحقق

52 tests across 8 files, all fast (~20–30s) because the shared fixtures default every ML/audio port to its stub: 52 اختبارًا عبر 8 ملفات، جميعها سريعة (~20–30 ثانية) لأن التركيبات المشتركة تجعل كل منفذ تعلّم آلي/صوت يستخدم نسخته الوهمية افتراضيًا:

Two things worth calling out. First, every ML-backed test (Qwen, Whisper) exercises the real model and self-skips — never fails — when the model or its dependencies aren't available, so the suite stays green in constrained environments without losing real coverage where it is available. Second, every feature in this report was also checked against a real running uvicorn server with curl and, for the WebSocket route, a real WS client script — not just the test harness — before being called done. أمران يستحقان الذكر. أولاً، كل اختبار مدعوم بتعلّم آلي (Qwen، Whisper) يُشغّل النموذج الحقيقي فعليًا ويتخطّى نفسه تلقائيًا — لا يفشل أبدًا — إن لم يتوفر النموذج أو اعتمادياته، فتبقى الحزمة خضراء في البيئات المقيَّدة دون خسارة تغطية حقيقية حيث تتوفر. ثانيًا، كل ميزة في هذا التقرير جرى التحقق منها أيضًا مقابل خادم uvicorn فعلي يعمل، باستخدام curl، ولمسار WebSocket سكربت عميل WS حقيقي — لا الاعتماد على حزمة الاختبار وحدها — قبل اعتبارها منجزة.
